## Phase 1: Obligated Entity Submission

**Actor:** Obligated Entity (e.g., Cement Manufacturing Ltd)  
**Page:** `/submissions/page.tsx`  
**URL:** `/submissions` (when logged in as obligated-entity)

### What Happens
1. Obligated Entity logs in with role `obligated-entity`
2. Navigates to "Submissions & Data Management"
3. Clicks "Choose DMRV Data Files" button
4. Selects CSV file with activity data (fuel, electricity, production)
5. File uploads and displays in "Uploaded Carbon Data" section
6. System calculates GEI, carbon credits, data quality score
7. Submission status: `pending-verification`

### Data Captured
- Activity data (fuel type, quantity, consumption)
- Calculated metrics (GEI, carbon credits, data quality)
- Timestamp of submission
- Entity metadata (name, period, location)

### System Actions
- Generates automatic audit log entry
- Triggers ACVA workflow notification
- Status: Changes to `pending-verification`

## Phase 2: ACVA Verification & Comment Generation

**Actor:** ACVA Verifier (e.g., Dr. Priya Sharma, TUV-SUD India)  
**Page:** `/submissions/[id]/review/page.tsx`  
**URL:** `/submissions/{SUB-001}/review`

### What Happens
1. ACVA Verifier logs in with role `acva-verifier`
2. Sees submission in verification queue
3. Clicks submission to open review detail page
4. System **auto-generates 7 domain-specific validation comments** based on:
   - Data quality checks
   - GEI calculation verification
   - Fuel consumption patterns
   - Evidence completeness
   - Compliance with CCTS regulations
5. Comments appear with severity levels: CRITICAL, MAJOR, MINOR
6. ACVA can:
   - **Edit any auto-generated comment** (changes text, marks as "Modified by Reviewer")
   - **Delete comments** that don't apply
   - **Add new custom comments** specific to this submission
   - **Set due date** (default: 14 days, range: 7-30 days)
7. Clicks "Send Review Comments"
8. Confirmation dialog shows comment summary
9. Comments sent to submitter
10. Submission status: `needs-resubmission`

### Data Structures

**ReviewComment Interface:**
```typescript
{
  id: string
  submissionId: string
  reviewerRole: 'acva-verifier' | 'check-verifier' | 'bee-officer'
  reviewerName: string
  reviewerOrganization: string
  commentType: 'CRITICAL' | 'MAJOR' | 'MINOR' | 'QUERY' | 'CAR'
  severity: 'critical' | 'major' | 'minor'
  commentText: string
  relatedField: string // e.g., "Fuel Consumption Data"
  createdAt: Date
  dueDate: Date
  resolutionStatus: 'OPEN' | 'RESPONDED' | 'RESOLVED'
  isAutoGenerated: boolean
  modifiedByReviewer: boolean // true if ACVA edited auto-generated comment
  modificationHistory: Array<{
    modifiedAt: Date
    modifiedBy: string
    previousText: string
    newText: string
  }>
}
```

### Comment Editor Features

**ACVAReviewEditor Component** (`components/acva-review-editor.tsx`):
- Summary cards showing count by severity
- Comment list with severity badges
- Edit mode: Click "Edit" → inline textarea → "Save" or "Cancel"
- Delete mode: Click "Delete" → confirmation → removes from list
- Add mode: Click "Add Comment" → form with severity, field, text
- Due date slider: 7-30 days
- Confirmation dialog before sending
- Full audit trail of modifications

## Phase 3: Obligated Entity Response & Evidence Submission

**Actor:** Obligated Entity  
**Page:** `/submissions/[id]/feedback/page.tsx`  
**URL:** `/submissions/{SUB-001}/feedback`

### What Happens
1. Obligated Entity sees notification: "Review Comments - Response Required"
2. Navigates to feedback page
3. **Views all comments from ACVA** organized by:
   - Severity (CRITICAL → MAJOR → MINOR)
   - Each comment shows: reviewer name, severity, related field, due date
4. **For each comment, entity must:**
   - Read the comment
   - Provide written response explaining how they addressed it
   - Upload supporting evidence (corrected data, test reports, certificates, etc.)
5. **Timeline tracking:**
   - Days remaining counter
   - Due date display
   - Days remaining visual indicator (green >7 days, amber <7 days)
6. Entity clicks "Submit All Responses"
7. Confirmation dialog shows response summary
8. Responses submitted
9. Submission status: `response-submitted`

### Data Captured per Comment
```typescript
{
  commentId: string
  entityResponse: string // Text explanation of how issue was addressed
  attachments: File[] // Supporting evidence documents
  submittedAt: Date
  responseStatus: 'submitted' | 'acknowledged' | 'accepted' | 'rejected'
}
```

### UI Features

**Entity Feedback Page:**
- Comment list (left sidebar): Click to select comment
- Response editor (right main area):
  - Comment display with severity badge
  - "Your Response" textarea (required)
  - "Supporting Evidence" file attachment area
  - Status indicator: "Response ready for submission"
  - Days remaining counter (urgent if <7 days)
- Submit button: Enabled only when all comments have responses
- Success alert after submission

## Phase 4: Check-Verifier Independent Review

**Actor:** Check-Verifier (e.g., Mr. Rajesh Kumar, Bureau Veritas)  
**Page:** `/submissions/[id]/check-review/page.tsx`  
**URL:** `/submissions/{SUB-001}/check-review`

### What Happens
1. Check-Verifier logs in with role `check-verifier`
2. Navigates to check-review page
3. **Tab 1: ACVA Comments**
   - Views all ACVA findings
   - Can **challenge any ACVA finding** by:
     - Clicking "Challenge" button
     - Providing rationale explaining disagreement
   - Challenged comments are flagged for ACVA escalation
4. **Tab 2: Entity Responses**
   - Views how entity responded to ACVA comments
   - Reviews supporting evidence provided
   - Can add follow-up comments for entity
5. **Tab 3: Independent Issues**
   - Can add independent findings not covered by ACVA
   - Examples: sampling methodology issues, data consistency, documentation gaps
6. Summary shows:
   - Count of challenged items
   - Count of entity responses
   - Total independent issues found
7. Clicks "Submit Report to BEE Officer"
8. Submission status: `check-verified`

### Challenge Mechanism
```typescript
{
  challengeId: string
  acvaCommentId: string
  challengedBy: string // Check-Verifier name
  challengeRationale: string // Why they disagree with ACVA
  severity: 'accept' | 'partial' | 'reject'
  createdAt: Date
  acvaResponse?: string // ACVA's reply to challenge
}
```

## Phase 5: BEE Officer Final Review & CCC Issuance

**Actor:** BEE Officer (e.g., Senior Officer, Bureau of Energy Efficiency)  
**Page:** `/submissions/[id]/final-review/page.tsx`  
**URL:** `/submissions/{SUB-001}/final-review`

### What Happens
1. BEE Officer logs in with role `bee-officer`
2. Navigates to final review page
3. **Views Overview Tab:**
   - Verification summary (ACVA, Check-Verifier names)
   - Comment statistics (total, challenged count)
   - CCC calculation display with confidence factor
   - Data quality score
   - **Final Compliance Checklist:**
     - Data Quality Score ≥ 70%
     - All ACVA Comments Resolved
     - Check-Verifier Approved
     - GEI Calculation Verified
     - Entity Compliance: Green
     - Documentation Complete
     - Blockchain Ready
4. **Views Verification Trail Tab:**
   - Complete audit timeline from submission to current stage
   - Each entry shows: actor, date, action, status
5. **Views Compliance Notes Tab:**
   - Can add final BEE Officer remarks
   - Remarks recorded in compliance certificate
6. **Compliance Checklist:** All items show ✓ (green checkmark)
7. Clicks "Submit to NSCICM for Approval"
8. **Workflow Steps Display:**
   - Step 1: BEE Prepares ✓ (Ready)
   - Step 2: NSCICM Review ⏳ (Pending)
   - Step 3: Central Govt ⏳ (Pending)
   - Step 4: Issue CCC ⏳ (Pending)
9. Confirmation modal appears showing 6-week approval timeline
10. BEE Officer confirms submission
11. System initiates NSCICM review workflow
12. Submission status: `submitted-for-ccc`

### CCC Calculation
```typescript
{
  cccGenerated: number // e.g., 14,850 CCCs
  confidenceFactor: number // 0-1 (e.g., 0.95 = 95% confidence)
  gei: number // kg CO2e/tonne
  dataQuality: number // percentage (e.g., 87%)
  period: string // Q1 FY2024-25
  entity: string // Cement Manufacturing Ltd
  baselineYear: number // For GEI baseline comparison
}
```

## Complete Workflow Data Flow

### Status Progression
```
pending-verification
    ↓ (ACVA sends comments)
needs-resubmission
    ↓ (Entity submits response)
response-submitted
    ↓ (Check-Verifier reviews)
check-verified
    ↓ (BEE Officer approves)
submitted-for-ccc
    ↓ (NSCICM + Central Govt review)
ccc-issued
    ↓
archived
```

### Comment Status Progression
```
OPEN (ACVA creates)
    ↓ (Entity responds)
RESPONDED (Entity submits evidence)
    ↓ (ACVA/Check-Verifier reviews)
RESOLVED (All parties satisfied)
```

## Key Features Implemented

- 7 domain-specific comments generated per submission

- Comment types: CRITICAL, MAJOR, MINOR

- Track modifications with **modification history**
- ACVA can **delete** irrelevant comments

### 4. Independent Review Mechanism
- Check-Verifier can **challenge ACVA findings**

- Separate tab for each concern type

### 5. Compliance Checklist & Closure
- BEE Officer sees 7-point compliance checklist
- All items show green checkmark when complete
- Complete audit trail visible throughout
- Final remarks can be attached before CCC issuance

### 6. Full Audit Trail
- Every action logged with timestamp
- Actor identification (who performed action)
- Status changes recorded
- Timestamps on comments, responses, reviews
- Complete modification history

### 7. Status Tracking
- Submission moves through 6 distinct states
- Comments track resolution status
- Visual indicators (badges, counters)
