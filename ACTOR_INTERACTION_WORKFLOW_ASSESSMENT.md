## What Exists Today (Data Layer Foundation)

### ✓ Data Structures in Place

**1. Query Interface** (`dmrv-types.ts`):
```typescript
- id, submissionId, raisedBy (ACVA), type, title, description
- dueDate (7 days per CCTS regulation)
- responseNotes, respondedAt, respondedBy (entity)
- status: 'open' | 'responded' | 'closed'
- acvaComment (ACVA assessment of entity response)
```

**2. CAR Interface** (Corrective Action Request):
```typescript
- id, submissionId, raisedBy (ACVA)
- type, title, description, nonConformity, evidenceOfNonConformity
- dueDate (14 days per CCTS regulation)
- correctionProposed (entity response)
- revisedDataProvided, correctedSubmittedAt
- status: 'open' | 'responded' | 'accepted' | 'rejected'
```

**3. ReviewComment Interface** (Enhanced):
```typescript
- submissionId, reviewerRole ('acva-verifier' | 'check-verifier' | 'bee-officer')
- reviewerName, reviewerOrganization
- commentType: 'CRITICAL' | 'MAJOR' | 'MINOR' | 'QUERY' | 'CAR'
- severity, commentText, relatedField
- createdAt, resolvedAt
- entityResponse, entityResponseDate (submitter response)
- resolutionStatus ('OPEN' | 'RESPONDED' | 'RESOLVED')
- isAutoGenerated (boolean - ML/rule-based)
- modifiedByReviewer (boolean - reviewer edited auto-generated)
- modificationHistory (track changes)
- actionRequired, daysSinceCreated
```

**4. CommentThread Interface**:
```typescript
- submissionId, queryId/carId
- comments: Array of {id, author, authorRole, message, timestamp, isSystemMessage}
- lastActivityAt
```

## What's MISSING (The Critical UI/Workflow Layer)

### ❌ PHASE 1: ACVA to Entity (Queries & Comments)

**Missing Workflow:**
1. ACVA Verifier sees submission in "Ready for Review" status
2. ACVA opens submission → Auto-generated comments appear
3. ACVA can:
   - Edit auto-generated comments
   - Delete unwanted comments
   - Add new custom comments
   - Set severity level
   - Attach documents/evidence
4. ACVA clicks "Send Review Comments" 
5. Comments go to Submitter with status "Needs Resubmission"
6. Due date: 7-14 days for entity to fix

**Missing Components/Pages:**
- `app/submissions/[id]/review/page.tsx` - ACVA review detail page
- Enhanced `acva-review-editor.tsx` - Full comment CRUD (Create, Read, Update, Delete)
- Auto-comment generation pipeline integration
- "Send Review" button workflow

### ❌ PHASE 2: Entity Response Back to ACVA

**Missing Workflow:**
1. Submitter (Obligated Entity) sees "Review Comments Pending" on dashboard
2. Views all comments by reviewer name, severity, field affected
3. Can see comments by:
   - ACVA Verifier (Dr. Priya Sharma)
   - Check-Verifier (Rajesh Kumar)
   - BEE Officer (if applicable)
4. Entity responds to each comment with explanation + uploads evidence
5. Entity submits response → goes back to ACVA with status "Response Submitted"
6. Entity can re-submit revised data

**Missing Components/Pages:**
- `app/submissions/[id]/feedback/page.tsx` - Entity feedback/response page
- Review comments display for entity (read-only + response field)
- Comment response editor
- Evidence upload for each comment
- Re-submission workflow

### ❌ PHASE 3: ACVA Review of Entity Response

**Missing Workflow:**
1. ACVA sees comment status changed to "Response Received"
2. ACVA reviews entity's response + provided evidence
3. ACVA can:
   - Accept response (comment closes)
   - Request more information (reopen with follow-up question)
   - Reject response (request more evidence)
4. ACVA can now add follow-up comments

**Missing Components/Pages:**
- "Response Review" mode in ACVA editor
- Accept/Reject/Reopen buttons
- Follow-up comment functionality
- Evidence preview UI

### ❌ PHASE 4: Check-Verifier Independent Review

**Missing Workflow:**
1. Check-Verifier sees verified submissions awaiting final review
2. Can view ACVA's verification report + all comments/CARs
3. Can independently add check-verification comments
4. Can accept or challenge ACVA's findings
5. Comments feed back to ACVA (if challenge raised)

**Missing Components/Pages:**
- `app/check-verification/[id]/review/page.tsx`
- Challenge/confirm workflow UI
- Independent comment editor

### ❌ PHASE 5: BEE Officer Decision

**Missing Workflow:**
1. BEE Officer sees verified submission with all comments resolved
2. Can see comment history (who said what, timeline)
3. Before final CCC issuance, can add final compliance comments
4. Issuance triggers closure of all comment threads

## Data Flow Diagram (What Should Exist)

```
SUBMITTER (Obligated Entity)
       ↓ Uploads DMRV data
ACVA VERIFIER (Dr. Priya Sharma)
       ├→ Reviews data
       ├→ Auto-generated comments appear
       ├→ Edits/adds/deletes comments
       ├→ Sends review to submitter
       ↓ (7-14 day due date)
SUBMITTER 
       ├→ Sees comments by reviewer
       ├→ Reads severity/explanation
       ├→ Responds to each comment with evidence
       ├→ Re-submits revised data
       ↓
ACVA VERIFIER
       ├→ Reviews entity response
       ├→ Can accept or request more info
       ├→ Updates comment status
       ↓ (if additional issues)
SUBMITTER
       └→ May need to respond again (loop)
       
       ↓ (When ACVA satisfied)
CHECK-VERIFIER (Rajesh Kumar)
       ├→ Reviews ACVA verification
       ├→ Can challenge findings
       ├→ Adds independent comments
       ↓
BEE OFFICER
       ├→ Final review of all comments
       ├→ Adds compliance remarks if needed
       ├→ Issues CCCs (closes all comment threads)
       ↓
ICM REGISTRY (Blockchain)
       └→ Final registration
```
